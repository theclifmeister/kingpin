# The profile: characters, unlocks and the daily

**The profile is the game around the runs** (#50, §6.7 "Meta-unlocks between runs" and "Daily seed for leaderboards"; `game/profile.go`, `content/characters.toml`, `content/characters.go`, `sim.NewWorldWith`, `ui/newrun.go`, `harness/characters.go`).
A run is a run: what the profile remembers (the runs that ended, the unlocks they earned, the dailies) only changes what a run *starts as*, applied once at `NewWorld`, and **no sim reads the profile or the character**, so a seed with the same start plays identically under any profile (`TestProfileNeverTouchesTheRun`: the default character on seed 11 for sixty days of `crewed` digests the same with no profile, an empty one and a full one under `KINGPIN_HOME`, and `sim.NewWorldWith(cfg, seed, Start{Character: "dealer"})` is `sim.NewWorld(cfg, seed)`), and a character moves the world on day 0 alone (`TestCharacterIsDayZero`: a character's day-0 world differs from the default's, and the run from it with `World.Start` wiped is byte for byte the run with it kept, to day 60 under `laundered`).

**The file.**
`profile.json` under `game.SaveDir()` (`KINGPIN_HOME`, beside the slots; `game.ProfileFile`, `ProfilePath`), JSON, its own `ProfileSchema` (1), written atomically as a world is (`SaveProfile`: temp file then rename).
`Profile{SchemaVersion, Runs []RunRecord, Unlocks map[string]bool, Best map[string]Score, Attempts map[string]int, Presets []Preset}` (the operation presets saved, #357, `docs/presets.md`: the routine as it stood, applied through the session's commands, so a profile with presets plays the same runs; none in a profile from before, no schema bump); `RunRecord{Seed, Character, HardDA, Ending (the cause), Score, Days, PeakCash, Stage (the highest stage's id), Date (the day it ended, `DailyKey`'s form), Daily (the date where the run was one), Practice}`; `Score{Score, Seed, Character, Ending, Days}`.
`LoadProfile(now)`: a missing file is `NewProfile()`; one that does not parse, or has no schema, is **set aside** as `profile.json.corrupt-<YYYYMMDD>` (`-2`, `-3` where the day has one already; `setAside`), never written over, and returned empty with `ErrCorruptProfile` naming the file kept, so the UI writes a fresh one beside it (`TestCorruptProfileIsKept`); one from a newer build is returned empty with `ErrNewerProfile` and left where it is, the run unrecorded (`TestProfileRoundTrip`, `TestCorruptProfileIsSetAside` in `ui`).
**Only the UI writes it** (`Model.loadProfile` in `wire`, `saveProfile`; `Model.now`, `time.Now` by default and a test's fixed date otherwise): when a run ends (`Model.finish`, `recordRun`: every path to `modeOver`, the morning's, a fast-forward's, the walk-away dialog's and a save continued), when a daily starts and when a preset is saved or deleted (#357); never a sim, never the harness, which measures a character with no profile at all.
`Profile.Record(chars, prog, rec)` files the record once (the same seed, start, cause, day and score is an ended save opened again: `TestRunEndRecordsAndUnlocks`), puts a daily's first attempt in `Best[date]`, applies `Unlocks` and returns the ids newly opened for the summary.

**Unlock rules** read `Ending.Cause` and the stage the run reached (#146: there is no tier mechanic, the stage is the highest `[[tier]]` of `progression.toml` reached, `World.Stage(prog)` its id).
`content.UnlockRule{Always, Ending, Stage}`, exactly one set (`validate`: a cause of `content.Causes`, a stage id of the ladder); `game.Met(rule, prog, cause, stage)`: an ending rule on its cause, a stage rule on that stage or any past it (`prog.Index`), an always rule never (it needs no unlock); `game.Unlocks(chars, prog, cause, stage)` is every character and the toggle the run opens, in file order; `Profile.Unlocked(rule, id)` is always, or earned.
The table (`TestEveryUnlockRuleFromAnEnding`): `vanished` opens the Ex-Cop, `businessman` the Bookkeeper, `kingpin` the `hard_da` toggle (`game.HardDAID`), reaching `distribution` (or `cartel`) the Dockhand, whatever the cause; nothing else opens anything.

**Characters are starts, nothing more.**
`characters.toml` `[[character]]`: `id`, `name`, `blurb`, `[character.unlock]` and `[character.start]` (`content.StartConfig`: `crew` roles on the payroll from day 0, `upgrades` nodes owned, `products` on the ladder in every city, `city` and `corner` where you stand, `corners` the corners held on day 0 with the start crew posted on them in order, a runner working one, an enforcer guarding one (#232; `validate` wants each in the start city, once, and not the corner you stand on; `sim.applyStart` holds them and posts through `World.Post`, a corner nobody works drifting as any does), `[character.start.reputation]` the three axes, `know_chief`); the first row is the default (`Default`, `IsDefault`: an empty id reads as it), always unlocked with an empty start, the run as it is (`validate` refuses otherwise, an unknown role, node, product, city or corner, a corner without its city, a reputation outside 0..100, or a second toggle field).
`sim.NewWorldWith(cfg, seed, game.Start)` is `NewWorld` with the start applied **after** the sims have seeded the world on the day-0 stream (the pool, the table, the law and the connects are the seed's whatever the character: `TestCharacterStartsAreDeterministic`) and before the first day steps; `sim.NewWorld(cfg, seed)` is `NewWorldWith(cfg, seed, Start{})`, byte for byte.
The character's own dice are `Tick{Day: 0}.Sub(game.StreamCharacter)`, never the home stream: `crew.Sim.Join(w, role, rng)` puts a member of the role on the payroll for nothing, hired day 0, with a name from the pool's list for the role (the chemists' for a chemist, the drivers' for a driver, the crew's for the rest) and the same `roll` `generate` makes (#275), off that stream (a lieutenant joins unassigned with a temper); `market.Sim.List(w, id)` lists a product in every city as `unlock` would the morning the peak cash earned it, before the connects are priced so they price it; a node is granted through `BuyUpgrade` with its prerequisites first and the cost handed over (`sim.grant`, `harness.Own`'s way, so a carry bonus or a supplier discount lands as a purchase would and nothing is reported); a city start gives home's starting corner back to the street (`Abandon`), travels and posts you on the corner named; the reputation is set; `know_chief` files `Fact{SubjectChief, FactPersonality, the chief's temper, confidence 1, day 0, SourceSeen}`, which never fades and which the law sim unlearns on a new chief as it does any.
`World.Start` (`game.Start{Character, HardDA, Daily, Practice}`) is stamped for the summary and the profile, read by neither sim nor harness; the default is stamped `""`.
**No schema bump**: the zero value is every run before; `TestSeedDigest` moved on day 1 by shape alone (with the field skipped the digest is 1a51f43's on all sixty days).

**Rulings and why.**
The Heir (#232) is New Game+, the kingpin ending's character beside the Hard DA toggle: the issue's start, an enforcer and a runner on two of home's corners, flipped the ordering the difficulty tests pin on 3 of 10 seeds (quiet over managed: a runner selling from day 0 is a second hand for the lone trader), so it shrank to one corner and no runner as the issue said to, and passes on ten (the aggressive trader lasts 11 days against 15: the notoriety is heat on every unit moved by hand, `notoriety_heat`, which is the character).
The ex-cop owns the *scanner*, not the issue's *lawyer*: with one page less a sting the aggressive trader lasts 22–24 days instead of 14–17 and the quiet trader out-earns it over that span on 6 of 20 seeds, so the lawyer fails "greed pays short term" and is a cheat by the acceptance's own reading; the scanner (`sting_stock_mul` 0.7, `cooldown_bonus` 1, "You hear the call go out before the car pulls up", an ex-cop's node if any is) passes on twenty.
The port start stands on the **Fish Market** (heat 0.9, demand 1.0, no taste) and not the wharf (heat 0.5 × the city's 0.85): on the wharf the aggressive trader lasted 74–157 days; on the boardwalk the crewed player was indicted on every seed.
The dockhand starts in Bayport, where no faction lives, so since #341 its take there draws one (scouts, recruiters poaching its crew, an arrival onto a free corner): the start is harder than it was, and meant to be (the city you start in is the city you must hold).
It stays a start, not a handicap, because the faction is answerable the way it is for anyone: the harness's crewed player hits the scouts (`harness.HitScoutsIn`, #379) and on seed 6 is indicted on day 146, as it was before #341; answering nothing it was indicted on day 113, under the tier-3 line `TestCharactersAreStartsNotCheats` holds, which is why that test ran boxed (`harness.NoExpansion`) until #379.
No new start was given the dockhand: a head start or a grace window on the move would be a rule a sim reads, and a character is a start on day 0 and nothing a sim reads.
The port start is the **rival-free city** (#43 seats every faction at home: `rivals.toml [factions] away` is 0, and turning that knob would change this number), so the crewed policy works six uncontested corners there and its median peak reads +137% (2.27M against 0.96M) while managed reads −31% and quiet −38% (Bayport halves the demand for coke and heroin): logged as the ruling asks, a reward for a player who has already reached Distribution, and not a number a band reads.
A day-0 crew member **takes a roster slot** (`max_crew` 6): the crewed policy holds five runners where the default holds six, and on the cook's seed 5 and the bookkeeper's seed 7 the rival takes the last corner and the fixed policy never re-posts, so `TestCharactersAreStartsNotCheats` reads the two orderings (managed > quiet, crewed > managed) on the **medians** of ten seeds and fails on more than one flip, while arrest within forty days, the quiet trader free and earning and greed paying over the aggressive span stay per seed; every median that moves more than 20% is logged and marked.
The default `sim.NewWorld` on a fresh install still starts a run in slot 1 (`ui.New`); `-slot N` on an empty slot opens the dialog for it.

**The daily.**
`game.DailyKey(date)` is the UTC date as `YYYYMMDD`; `game.DailySeed(date)` folds that number through one step of SplitMix64 (`z += 0x9E3779B97F4A7C15; z = (z ^ z>>30) * 0xBF58476D1CE4E5B9; z = (z ^ z>>27) * 0x94D049BB133111EB; z ^ z>>31`), so two dates share nothing and every process on every machine gets the same seed for a date: `TestDailySeedIsTheDate` pins 2026-09-13 at `0x8a76da7003db4145`, the same at 00:00:01 and 23:59:59 UTC, different on the 14th, and two runs on it identical.
A daily is the default character with the hard DA off (`Start{Daily: key, Practice}`); `Profile.StartAttempt(date)` counts the attempt on disk when the run starts (so a daily abandoned in a slot still counts) and the second and later are **practice**: recorded, marked, never scored, and `Best[date]` is the first attempt's alone (`TestDailyIsScoredOnce`, `TestDailyIsTheDate` in `ui`).
`time.Now` is read in the UI alone (`Model.now`, `newSeed`, the start menu's date, the profile's; `TestNoWallClockInTheSims` parses every non-test file under `internal/game`, `internal/sim`, `internal/content`, `internal/harness` and `cmd/balance` and fails on `time.Now`, `Since` or `Until`), and every test passes a date.
No network: the leaderboard is your own history.

**The UI** (`ui/newrun.go`, `modeNewRun`, `newRunDialog{slot, step, cursor, seed numberField, hard}`; `docs/keys.md`, `docs/modals.md`).
`enter` on an empty slot of the start menu (and `-slot N` on one) opens the dialog, one modal with pages: the **character picker** (`pickRow`: every row of the file as a name and its blurb, a locked one greyed under `locked: <rule>` — `unlockRule`: `end a run vanished`, `end a run as a businessman`, `end a run as kingpin`, `reach Distribution` — and `Daily · 13 Sep 2026` under them with `the default character on the date's seed, one scored attempt`, or `a practice run, your first is the one scored` once the date has an attempt; `↑↓ pick`, `1-6 choose`, `enter next`, a locked row refused with its rule, `enter` on the daily starting at once), the **seed** (`Seed  > random`, a `numberField` in `numberStep`, blank is `newSeed()`, a typed one the run's; the toggle named as `Hard DA · locked: end a run as kingpin` under it while locked) and, once the profile has earned it, the **hard DA** (`Hard DA  [off]  on`, `←→ toggle`); `enter start` on the last page (`newRunStart`, `lastStep`), `⇧tab back`, `esc close` to the menu with nothing started (`TestPickerListsEveryCharacter`, `TestNewRunStartsTheCharacter`, `TestModalsFit`'s `new run: character / seed / hard DA` at 80x24 and 120x40).
`Model.startRunWith(seed, start)` is `startRun` with a start (`sim.NewWorldWith`), the status naming the character (`New run. The Cook. Eastside, $2,000 in your pocket. Seed 42.`); `Model.restart` is a new run as the run up began (the same character and hard DA, a fresh seed; a daily's is a run as the default character, not the daily again): `N`'s confirmation and **`n` on the summary**.
The start menu carries a **History** line under the rows once a run is recorded (`History · 12 runs · best $1.2M · 4 of 9 endings`, `historyLine`) and the profile's message in `theme.Warning` when loading set a corrupt one aside (`Profile: profile is corrupt (...): kept as profile.json.corrupt-20260913. Starting a fresh one.`).
The **summary** (`docs/endings.md`) says where the run ranks against your own history on the SCORE line (`· 3rd of 12 runs`, `rankLine`, this run counted, `Profile.Rank`: a higher score ranks above, equal shares) and, on its first line in gold, the daily's date (`· daily 13 Sep 2026`, `, practice`) and what the run unlocked (`· unlocked The Ex-Cop`, `unlockedLine`, `Model.unlocked`); `esc` on the summary closes it to the start menu, the ended save kept.
`character`, `daily` and `profile` are help WORDS.

**The harness** (`harness/characters.go`, `characters_test.go`).
`harness.Character(cfg, id)` is the `game.Start` for a character (an unknown id panics; `""` the default), `harness.RunAs(cfg, id, seed, days, policy)` plays `Run` as one, and `cmd/balance -character C` (`-hardda` beside it) starts every run as it, printing `character: cook (The Cook), hard DA false` under the policy line.
`TestCharactersAreStartsNotCheats` (parallel subtests, one a character, ~0.6 s each) runs the four difficulty tests as each on ten seeds as above and logs the aggressive trader's days and the medians of the managed, quiet and crewed peaks against the default's (the table above; the dockhand's three are the ones marked).
No band, ordering or `TestNo*IsTheOldRun` moved: the default character is the run as it is.
