# Saves

**Saves.** `World` is gob-serialised, one file a slot (`save.go`, atomic write, `SchemaVersion` guard): `game.SlotCount` (3) slots, `save<N>.gob` under `game.SaveDir()` (`KINGPIN_HOME`, else the platform config dir), and `Save(slot, w)`, `Load(slot, migrations...)`, `DeleteSave(slot)`, `HasSave(slot)` and `Slots() []SlotInfo` (`Slot`, `Day`, `Cash`, `City` name, `Saved` the file's mtime, `Empty`; read without a migration, so a file this build cannot load still shows and `Load` says why) take the slot, `ErrBadSlot` outside 1..3 (#121). The pre-slot `save.gob` is adopted as slot 1 the first time slot 1's path is asked for, renamed only while `save1.gob` does not exist (`TestOldSaveIsSlotOne`, `TestSlotsAreIndependent`); the format itself did not change, so no schema bump. The start menu (`modeStart`, `keyStart`, `viewStart`, `startRows`, `slotLine`) is the slots and Quit under one cursor: `Slot 1 · day 42 · $1.2M · Eastside · saved 2h ago` (`format.Cash`, `format.Ago`) or `Slot 2 · empty`; `enter` continues a full slot or starts a run in an empty one (`pickStart`, `continueRun(slot)`, `newRun(slot)`), `D` asks (`modeConfirm`, `deleteConfirm`, `y` deletes; `Nothing to delete.` on an empty slot or Quit) and a run that does not load leaves the menu up with the error on the slot, so a save from a newer build is deleted on purpose, never overwritten (`TestUnreadableSaveIsRefused`). A save that fails says so (#272): on the status line in play, and on the way out `Model.QuitErr` keeps it for `cmd/kingpin` to print once the screen is back (`TestQuitKeepsAFailedSave`). `Model.slot` is where `ctrl+s`, the end of the day, quitting and `N` (still `modeConfirm`, starting over in the same slot as the same character, #50) save; `ui.New` shows the menu when any slot is full and starts in slot 1 on a fresh install, `ui.NewSlot(cfg, n)` is `cmd/kingpin -slot n` (a full slot continues, an empty one opens the new-run dialog for it: the character, the seed, the hard DA, `docs/profile.md`, #50; before #50 it started the run at once); the title bar does not show the slot. Beside the slots sits `profile.json` (#50, `docs/profile.md`): the runs that ended, the unlocks and the dailies, its own schema, set aside as `profile.json.corrupt-<date>` when it does not read, and never a sim's. `TestStartMenuLists` pins the lines at 0, 1 and 3 full slots, `TestModalsFit` opens the menu with three full slots and the delete confirmation (`fillSlots`), `TestSaveRoundTripIsDeterministic` runs per slot. The 12 -> 13 step (#47) is `market.Sim.MigrateLots` over `World.MigrateLots`: every lot holding anything, every shipment and every connect's product gets the default quality and every corner `repeat_start`, so an old save plays on as it did (`docs/quality.md`). Bump `SchemaVersion` when `World` changes shape incompatibly and add a `game.Migration` step for the previous version to `sim.Set.Migrations` (gob fills missing fields with zero values, so a step usually only seeds the new state); `Load` walks the chain per file and refuses saves it has no path for, or that are newer than the build. The 13 -> 14 step (#46) is `crew.Sim.MigrateAges`: every member and candidate without an age gets one off `Tick{Day, Seed}.Sub("ages")`, never the home stream, so the run replays as it did (`docs/crew-life.md`); the other #46 fields are zero values. #48's assets need no step (the issue asked for a bump): `World.Assets` and `AssetsLost` nil, `Stats.PeakClean` zero and caught up the first `EndDay`, the heat state's task-force fields zero, and the plane and the tunnel content that an old save's `Routes` map simply has no entry for. The 14 -> 15 step (#43) is `rivals.Sim.MigrateFactions`: `World.SeatRival` seats the save's one `Rival` (read off the stream a second time as `v14`, since gob drops a field the receiver lacks) as the first of `World.Rivals`, and the table is seeded beside it off `game.SubRNG(seed, 0, "factions")`, the factions a fresh run of that seed would have dealt, arriving on their days from wherever the save is (`TestSaveSeatsTheOneRival`); `Deal.Faction`, `Offer.Faction` and the rest are zero values that read as the rival at home's.
The 15 -> 16 step (#45) is `game.MigrateBooks`: `Rival.Known`, the books a scout read, is gone (the read is four facts in `World.Intel`), so `Load` reads the old field off the stream a second time as `v15` (on every faction, and on a pre-15 save's one `Rival`) and files a read snapshot as the facts on the day it was read, fading from there as a fresh read would (`TestSaveFilesTheBooksRead`); every other #45 field is a zero value (`docs/intel.md`). The four second reads (`v6` before 7, `v9` before 10, `v14` before 15, `v15` before 16) are one table, `legacyReads` in `save.go` (#275): a row is the schema it applies below and the read that decodes the stream again (`decodeAgain[T]`) and hands the old shape to the field its migration consumes; `Load` runs the rows in order before the migrations and clears `legacy`, `old` and `books` after them. A new shape that gob cannot carry across is a row there.
