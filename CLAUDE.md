# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workflow rules

Every change follows the same path. Do not skip steps.

1. **Start with an issue containing the plan.** Before writing code, open a GitHub issue (`gh issue create`) that states the goal, scope and acceptance criteria. Phase work references the design in issue #1 ("Part of #1"). If an issue already exists for the work, use it.
2. **One branch per issue, holding all of its changes.** Never commit to `main`. Branch from an up-to-date `main` and keep every change for that issue on that branch. `main` is protected: changes land only through a pull request with green CI.
3. **Link the PR to its issue.** The PR body must contain `Closes #N` for the issue it implements, so merging closes it. If a PR deliberately deviates from the issue's spec, say so in the PR.

CI (`.github/workflows/ci.yml`) runs on pull requests only (never on `main`; it changes only through merged PRs) and checks gofmt, `go mod tidy` drift, `go vet`, staticcheck, `go build`, `go test -race`, and a short balance smoke run. Make the same checks pass locally before pushing.

## Commands

Go is installed via Homebrew and is not on the default shell PATH: prefix commands with `PATH=/opt/homebrew/bin:$HOME/go/bin:$PATH` or export it once.

```sh
go run ./cmd/kingpin                # play (needs a real terminal, >= 80x24)
go build ./... && go vet ./...
gofmt -l .                          # must print nothing
staticcheck ./...                   # go install honnef.co/go/tools/cmd/staticcheck@latest
go test -race ./...
go test ./internal/ui -run TestBuyThenSellFlow   # one test
go test ./internal/harness -run TestPriceInvariants -v

go run ./cmd/balance -policy managed -runs 50 -days 200   # headless balance numbers
go run ./cmd/balance -policy aggressive -seed 7 -trace    # per-day trace of one run
```

`cmd/balance` policies: `idle | hide | quiet | normal | aggressive | careful | managed | upgraded | crewed | territory | war | diplomat | laundered | funded | distributor | delegated`. An unknown policy silently falls back to `normal`. `-lielow N` overrides the lie-low threshold of the managed-style policies; `-corners N` caps how many corners `territory` and `war` work (`crewed` works as many as it can staff); `-force warn|push|hit` is how hard `war` sends the enforcers; `-rival P` forces the rival's personality; `-cash N` starts every run with that much dirty cash (`-policy hide -cash 5000000` is the rich player who sits on the pile); `-own a,b` starts every run owning those upgrades for free, prerequisites first (`harness.Own`). `laundered` is `crewed` plus fronts: it buys the cheapest front it lacks when dirty cash is 3x the price, runs the launder dial at normal and drops to careful for 30 days after an audit. `distributor` is `laundered` until the wholesaler deals with it, then moves to Bayport for good, keeps runners on the corners at home and the rest on the corners there, ships home every product that costs less here than it fetches there (the normal dial, the biggest route with room) and buys the next few days of home's demand behind it by the lot, buying the upgrade tree as `upgraded` does. `-cards decline|first` deals the dilemma cards and answers every one with its last or first choice; without it the harness plays with the deck in the box. `diplomat` is `territory` that proposes a truce whenever the rival has taken a corner off it in the last `harness.DiplomatDays` and pays tribute once the truce has been refused twice; it stays at home, where the rival is (`distributor` leaves for the hub). `delegated` is `distributor` that hires the first lieutenant looking for work (firing its least skilled runner to make room), gives them home, keeps `harness.HubCorners` runners on the hub's corners and leaves the rest idle for the lieutenant to post, fills the roster their people make room for, pays them off when their loyalty nears the flip line, and never posts or sells at home itself; `-lt violent|greedy|careful|steady` forces the temper of the lieutenant it hires (by default they come as generated). `funded` is `laundered` that gives the city it is in a quarter of its clean cash whenever the pressure there is over `harness.FundPressure` (60), up to what fills goodwill; `-chief corrupt|zealous|lazy` and `-da law_and_order|moderate|reform` force the law for the whole run (`harness.Appoint`: the actor is renamed and its clock stopped, so no election or term end replaces it), and the end medians print pressure and goodwill.

Set `KINGPIN_HOME` to keep test saves out of your real config dir (tests do this with `t.TempDir()`). To drive the TUI headlessly, run it under `tmux` and use `send-keys` / `capture-pane`; `internal/ui/ui_test.go` has a `key()` helper for feeding `tea.KeyMsg`s to the model directly.

## Architecture

The game is a set of independent, deterministic simulations stepped once per in-game day over a shared `World`, with a Bubble Tea UI on top. The pieces are wired in `internal/ui/model.go` (`New`) and `internal/harness` (headless).

**Day loop.** `game.Clock.EndDay` (`internal/game/clock.go`) builds a `Tick` with a per-day RNG from `game.RNGFor(seed, day)`, steps every `Simulation` in the fixed order `market -> logistics -> territory -> rivals -> crew -> heat -> law -> laundering -> reputation -> news`, then clears the player's per-day scratch (orders, buys, lie-low, strike, hires, fires, upgrades bought, the proposal, accepted offers, abandoned corners, funding) and publishes the tick's events on the `events.Bus`. Because RNG is derived from `(seed, day)`, nothing about randomness is saved and a run is reproducible from its seed; `TestDeterministicForSeed`, `TestDistributorIsDeterministicAndSaves` and `TestSaveRoundTripIsDeterministic` enforce this. Sims must stay deterministic given `(World, Tick)`. `Tick.RNG` is the home city's stream; anything that happens away from home (another city's market and robberies, the road) rolls on a side stream, `Tick.Sub(name)`, derived from the seed, the day and the name, so a run that never leaves Eastside replays exactly as it did before the second city existed and every seed-pinned balance number survived #30 unchanged. Keep it that way: a sim that adds dice for the second city draws them from a `Sub`, and so does the law (`Tick.Sub("law")` for an election and a new chief), so the home stream survived #41 too.

**Events are the cross-sim channel.** Sims never call each other. A sim emits typed events (`internal/events/events.go`, each with a stable `Kind()`) via `Tick.Emit`; later sims in the same tick read `Tick.Events()` to react (territory, crew and heat consume the market's `PlayerSold`, the crew sim for a lieutenant's cut and the heat sim for their temper; crew applies the rival sim's `CornerStruck` toll to enforcers by nerve; heat adds the heat carried on `CornerStruck`, `RivalTippedPolice`, a crackdown `WarEscalated` and the logistics sim's `ShipmentSeized`; the law sim counts the violence, the hard product on `PlayerSold` and an `Enforcement` that shows the chief's hand; news consumes everything). After the tick, the bus delivers events to the UI (`Model.onEvent`) for the ticker, alerts and journal. Adding an event kind means adding a headline template in `internal/content/headlines.toml` and listing it in `TestEveryEmittedEventHasTemplate`, unless it is report-only bookkeeping like `PriceMove`, `CrewPaid`, `RivalUndercut`, `ShipmentSent`, `ShipmentArrived`, `LieutenantActed` or `CityFunded`, or deliberately silent like `CrewTurnedInformant` and `LieutenantFlipped`.

**World is a plain struct** (`internal/game/world.go`) that sims mutate directly. Player actions (`Buy`, `BuyWholesale`, `PlaceSell`, `CancelSell`, `Ship`, `Travel`, `SetLieLow`, `Hire`, `Fire`, `SetPay`, `Investigate`, `PayOff`, `BuyFront`, `SetLaunderDial`, `Assign`, `Unassign` in `actions.go`; `Fund` in `law.go`; `Post`, `Recall`, `Abandon`, `SendEnforcers`, `CallOff` in `territory.go`; `Propose`, `Withdraw`, `Accept`, `Decline` in `diplomacy.go`) only queue intent (or, for a buy, a shipment and a trip, apply at once and are reported); the market sim resolves sell orders during `EndDay`, the crew sim reports hires and fires, the territory sim reports claims, the rival sim resolves the strike and answers the proposal and seals the accepted offers, the laundering sim reports front purchases, the logistics sim moves the shipments, the law sim turns the day's funding into goodwill, and the morning `DayReport` is what the UI shows.

**Cities** (#30). `World.Cities` (keyed by id, `CityOrder` fixing the sequence, home first) holds what is per city: a `City` has its own `Market` (per-product `ProductMarket`, priced by `[city.market]` multipliers in `city.toml` on the ladder in `market.toml`, so coke is cheap in Bayport and weed is dear), its own `Corners`, its own `Heat` (0..100) and its static `HeatMul` and `Wholesale` flag. `World.Home()` is the first city (where a run starts and the only city the rival fights over: the rivals sim reads `w.Home().Corners`), `World.Here()` the one the player is in (`Player.Location`). Stock is a stash per city, `Player.Stash[city][product]` (`w.Stash(city)`, `w.Stock(city, id)`), and moves between cities only by shipment; `World.Capacity(city)` is what the supplier there will sell into: the carry limit if the player is there, plus runners posted on corners there, plus idle runners wherever the player is, and `Free(city)` is what is left of it. `Buy` is from the supplier where the player stands, into the stash there; `Travel(city)` moves the player at once, recalls `You` from their corner (it drifts unless a runner takes it) and leaves the stock; `Post(corner, You)` is refused outside the player's city (`ErrElsewhere`), runners go anywhere. Sell orders are per city (`OrderKey(city, product)`, `w.Order`), resolved by the market against that city's worked corners, so a `PlayerSold` in a city the player is not in is the runners there (`TestSalesElsewhereAreRunnersOnly`). `Corner.City` says which city a corner is in; ids are unique across cities (content refuses otherwise) so `w.Corner(id)`, `w.PostOf(id)`, `Held()`, `Worked()` and `RivalHeld()` search every city, `WorkedIn`, `HeldShare` and `Demand` take a city, and `Borders` never crosses one. `PriceMove`, `PriceShock`, `PlayerSold`, `HeatChanged` and `Enforcement` carry the `City`. `SchemaVersion` is 9 (7 was the cities, 8 the rival's trust, 9 the chief and the DA): `Load` reads a pre-7 save's single-city fields (`Market`, `Territory.Corners`, `Player.Stock`, `Heat.Value`) off the stream a second time into an unexported `v6` record and `World.MigrateCities` wraps them into the home city (`logistics.Sim.Migrate` then lays out every other city in the config with every product the run has unlocked, and `territory.Sim.Migrate` runs again to seed corners for cities that have none), so an old save is a two-city world whose home city plays on identically (`TestSaveMigratesTheOneCity`, `TestOldSaveIsMigrated`).

**Corners are the demand.** Each city's `Corners` (seeded from `internal/content/city.toml`, one `[[city]]` per city with its `[[city.corner]]`s) each carry a size, per-product `Taste`, a heat multiplier and a robbery `Risk`. `ProductMarket.Demand` is per *standard corner* in that city; what the player can sell there is `World.Demand(city, product)` = that times `HeldShare(city, product)` (the summed shares of corners there that are `Worked()`: owned and with a runner, or `game.You`, posted). A held corner with nobody on it drifts back to `none` after `drift_days`; an enforcer posted on a corner cuts its robbery chance; a robbery takes from the stash of the corner's city. `Fire` and crew quits `Recall` the member so a corner never points at someone who is gone. The heat sim weights every unit sold by the corner it moves on (`CornerWeight`: corner heat, and `crew_heat` for a runner's corner) and by the city's `HeatMul`, so where you sell matters as much as how much. Dirty cash over `dirty_cash_threshold` is heat too, where the player is, but only dealing builds a case: a sting or raid that fires on a day the player attempted no sale in that city (no `PlayerSold` there with `Wanted > 0`; lying low resolves none) still costs stock and cash and cools heat but adds no evidence, so a cash pile draws stings without being a countdown (#27, `TestRichHiderIsNeverIndicted`). Heat is per city and the case is personal: every city's heat takes its own sales, decays on its own and holds the fear floor; the war's heat lands at home, an informant's, an audit's and the cash pile's where the player is; and the *hottest* city's police answer at the thresholds (one response a day, the cooldown ladder and `Evidence` global), taking stock from the stash there. `Heat.Peak` is the hottest any city has been.

**The law has actors** (#41, `internal/sim/law`, `World.Law`, `City.Pressure`, `City.Goodwill`, tuning in `law.toml`, names in `names.toml`). A **police chief** (`Chief{Name, Personality, Since, Observed}`, `corrupt | zealous | lazy`) and a **DA** (`DA{Name, Stance, ElectedDay}`, `law_and_order | moderate | reform`) are drawn from the day-0 RNG after the crew and the rival (`law.Sim.Seed`; schema 8 -> 9 seeds them on an old save from the current day, `law.Sim.Migrate`). They are tables the heat sim multiplies *its own* tuning by, read off `w.Law` through `content.LawConfig` and never the other way: the chief's `cooldown` scales `cooldown_days` for stings and raids (the patrol keeps its cadence under every chief: it fires as often as its cap lifts, and one that came back sooner would never lift, which is what stops managed play paying at all), `cap` what a patrol lets through and `decay` the daily decay (`heat.Sim.CooldownDays`, `PatrolCap`, `Decay`); the DA's `evidence_arrest` scales the pages an indictment needs (`heat.Sim.EvidenceArrest`, over the retainer's) and `sting` the sting line (`heat.Sim.Threshold`). #27 holds throughout: the law moves thresholds, cooldowns and decay and never adds a page (`TestQuietDayRuleHoldsUnderEveryLaw` runs the rich hider under every chief and DA). **Pressure** is per city, 0-100: the law sim, stepping after heat (so the police answer on *yesterday's* pressure, the way reputation reads yesterday's journal) and before laundering, adds `[pressure]` sources (`CornerStruck`, `RivalPushed`, a flip and a crackdown at home; hard product, `hard_products`, per `hard_units` sold in the city; yesterday's headlines about you, `headline_sources` as notoriety's, where you are), fades it toward `baseline` by `decay` of the gap, takes `goodwill_cut x Goodwill/100` off it, and reports a band crossed (`PressureShifted`, headlines `PressureShiftedUp/Down`). What pressure does, each sim reads off `w.Law`'s city through `[effects]` in its own config: the heat sim cuts the patrol, raid and arrest thresholds of the city whose police answer by `pressure_threshold_cut` at 100 and what a patrol there lets through by `pressure_cap_cut` (the sting line is the DA's alone: it is where a case starts), the rival sim raises its tip chance by `pressure_tip` (`rivals.Sim.TipPace`, the home city's). **Goodwill** is bought with `World.Fund(city, amount)`, clean cash only (`ErrNoCleanCash`, whatever the dirty pile), queued in `World.Funded` scratch and converted by the law sim at `goodwill_cash` a point (`CityFunded`, report-only), capped at 100 and fading by `goodwill_decay` a day; it is what 4.9's legitimate ending will read. **Terms**: the chief serves `chief_term` days and is replaced on schedule (`ChiefReplaced{Why: "term"}`), the report naming their personality only once `Observed` (`observe_days` in office, or any patrol, sting or raid); **elections** every `term_days`: the law-and-order share of the vote is `0.5 + (mean pressure - 50)/100 x election_swing` (`law.Sim.LawAndOrderShare`), a moderate takes `moderate` of every vote whatever the mood, one draw from `Tick.Sub("law")` decides it, a win on the sitting DA's ticket re-elects them by name (`DAElected{Incumbent}`, headline `DAReElected`), and a law-and-order DA elected with the mean over `replace_pressure` replaces the chief at once (`ChiefReplaced{Why: "da"}`, `ChiefReplacedDA`). A term of 0 stops the clock (`harness.Appoint` uses it to hold a forced chief or DA for a run). The dashboard's LAW panel sits under the STREET panel (the chief and what they are like once observed with the days left, the DA and their ticket with the election countdown, the pressure bar where you are in heat's red with goodwill and the other city's number), the heat gauge's marks are `heat.Sim.ThresholdsIn(w, here)` so the ladder the player reads is the one the dice use, `f` on the ledger opens the fund dialog (`ui/law.go`, `modeFund`: left/right turn the city, an amount, blank fills goodwill to 100 from what is in hand), and the report has a LAW section (elections and new chiefs first). `harness/law_test.go` pins the acceptance: the aggressive trader is indicted sooner under a zealous chief than a lazy one and the hot crewed player sooner under a law-and-order DA than a reformer, pressure and goodwill stay in 0-100 under every policy, a hit war is louder than holding ground, the `funded` player ends quieter than `laundered` and gave only what its fronts washed, elections at pressure 80 return law-and-order more often than at 20 over 50 seeds and fire on schedule with a headline naming the winner, and the law survives a save. The harness policies that "pay attention" (`harness.TooHot`) lie low at the same fraction of the sting line as `heat.toml` prints it, and `RedMargin` lower once the file is within two pages of an indictment: the law moves the ladder the dashboard shows, and a scripted player calibrated to a fixed 55 would otherwise be stung on every seed that draws a zealous chief.

**Logistics is the road** (#30, `internal/sim/logistics`, `World.Shipments`, `World.Logistics`, tuning in `routes.toml`). `[[route]]` edges join two cities either way with a `mode` (car, truck, boat), `days` in transit, `capacity` per shipment, `cost` per unit (dirty) and `risk` of interception per day in transit; the ship dial `slow / normal / fast` (`events.Ship`, `[dial.*]`) multiplies the days (never under one) and the risk on each of them, so `logistics.Sim.Days`, `DayRisk` and `Risk` (the chance a shipment is seized at all, what the dialog shows) are what the dice use. `World.Ship(RouteOffer, from, to, product, units)` (priced by `logistics.Sim.Offer`/`Ship` so the world never sees the config) takes the units out of the source stash and the cost out of dirty cash at once, refuses more than the route carries or a second shipment on a route the same day, and puts a `Shipment` (`Sent`, `Arrives`) on the road; the sim, stepping first after the market so what lands sells tomorrow, reports it the next morning (`ShipmentSent`), rolls interception on every day in transit and either lands it in the destination stash (`ShipmentArrived`) or loses the lot (`ShipmentSeized`). Stock is conserved across a shipment and a seized one never arrives (`TestStockIsConservedAcrossShipments`); fast is seized more than slow (`TestFastIsSeizedMoreThanSlow`). A seizure is a market shock, not a bust (`TestSeizureIsShockNotEvidence`): the heat sim adds `seizure_heat` in both cities on the route and `seizure_evidence` only if the shipment was sent fast (#27: a case is built from what you did), and the market, which steps before logistics, reads the seizure off `Logistics.Seizures` the next morning and spikes the product in the city it was bound for by `shock_factor` for `shock_days` (`PriceShock.Seized`, headline `PriceShockSeized`); the record is kept `record_days`. `World.TotalStock()` counts the road, so wages never end a run while product is in transit; `NetWorth` values it at the destination's supplier price. `[wholesale]` is the supplier in a city marked `wholesale` selling `lot`-unit lots at `mul` of its street supplier price once peak cash reaches `unlock_cash` (`game.WholesaleOffer`, `World.BuyWholesale`): a lot goes to the dock, not the stash, so it is not held to the city's capacity, and only the road out limits how much of it moves. That, and Bayport's price multipliers, is where the tier-4 margin comes from; `distributor` is the policy that runs it and `TestDistributorBeatsLaundered` pins that it pays.

**Fronts are the laundering.** `World.Fronts` (bought with dirty cash through `BuyFront`, priced by `laundering.Sim.Offers` from `internal/content/laundering.toml`, gated by `unlock_cash` like products) each wash `min(throughput x dial.mul, dirty cash over the float)` from dirty to clean every day, pay `upkeep` in clean cash (unpaid, the front shuts for `upkeep_freeze_days`) and roll an audit at `audit_risk x dial.risk`; an audit freezes the front for `audit_freeze_days`, seizes `audit_seize` of what it washed that day and emits `FrontAudited`. `World.Laundering.Dial` (`careful | normal | greedy`, `events.Launder`) is a persistent setting like the pay dial. The wash never takes dirty cash below `float`, so fronts can never starve the street of restock money (that is what "broke" means). Laundering steps *after* heat, so heat reads yesterday's audit off the front's `Audited`/`AuditDial` record the next morning: `audit_heat` in `heat.toml` every time, plus `audit_evidence` only if the front was being run greedy (#27: a case is built from what you do). Accountants (`[role.accountant]` in `crew.toml`, only in the hiring pool once a front is owned) add `accountant_throughput` to every front and cut audit risk by `accountant_risk_cut`, both scaled by skill; a skimming accountant takes from the previous day's wash, in clean cash (`CrewSkimmed.FromWash`). `NetWorth` counts clean cash, stock at supplier price and fronts at cost.

**Reputation is the player's face** (#14, `internal/sim/reputation`, `Player.Reputation`, tuning in `reputation.toml`): three axes 0-100, `Fear`, `Respect`, `Notoriety`, that the reputation sim drifts from the day's events and fades toward `baseline` by `decay` of the gap a day. Sources: `CornerStruck` (taken or held) and `RivalPushed` are fear, `CrewPaid` at generous pay in full, `CrewPaidOff` and every night a truce or a split holds (`deal_kept`, read off `w.Rival.Deals`) are respect (a short payroll costs it), `PlayerSold` volume per `units`, a strike, and every headline about you are notoriety, where "about you" is a journal entry from yesterday whose source is in `headline_sources` (heat, crew, territory, laundering: market and flavour are the city's news, the rival's story is its own, and the strikes are counted directly). The sim steps after laundering and before news, so it reads yesterday's journal and the band it crosses today (`ReputationShifted`, a multiple of `band`, up or down, six headline keys `Reputation<Axis>Up/Down`) is today's news. The street has only so much attention: past `total` between the three every axis shrinks in proportion, so you cannot max all three (`TestReputationCannotMaxAllThree` feeds every source for the horizon and the sum holds at 200). The effects live in `[effects]` as what the axis does at 100, scaling linearly (`content.Scale` / `content.Cut`), and each is read by the sim that owns the number, from its own copy of `content.ReputationFX` and `w.Player.Reputation`, never through another sim: the rival's push *chance* (`rivals.Sim.PushPace`, fear) and what it makes of a proposal (`fear_deal`) and a kept deal-night (`respect_trust`), the crew's daily loyalty loss (`crew.Sim.LoyaltyLoss`, respect) and a candidate's signing fee (`crew.Sim.HireFee`, notoriety; fixed when the candidate is generated, so the pool catches up as it rotates), the supplier ratio (`market.Sim.SupplierRatio`, respect; the dashboard's supplier line reads it), and in the heat sim a floor heat decays toward and is never taken under (`heat.Sim.Floor`, fear) plus the weight of a unit *you* move on your own corner (`heat.Sim.PersonalHeat`, notoriety; a runner's units are theirs, so a notorious boss gets off the corner). The dashboard draws the three as one line of bars under the heat gauge (purple, blue, orange) and the game-over summary reports them; `cmd/balance` prints the end medians. `reputation_test.go` in the harness pins the acceptance: every axis in 0-100 and the sum under `total` on every day of every policy, a feared player carries more heat than a respected one at the same volume, no policy ends with all three above 70, each effect pulls its way, and the save round-trips (`TestSaveKeepsReputation`). The zero value is a nobody, which is what the pre-#14 world was, so no schema bump. Fear's floor and notoriety's personal heat are what moved the difficulty tests when they landed: the crewed player's late game sits a sale under the sting line, so the vigilant player in `snitch_test.go` lies low at 35, and `TestGreedyWashesMoreAndIsAuditedMore` reads its wash over five seeds rather than each.

**Saves.** `World` is gob-serialised as the single save slot (`save.go`, atomic write, `SchemaVersion` guard). Bump `SchemaVersion` when `World` changes shape incompatibly and add a `game.Migration` step for the previous version to `sim.Set.Migrations` (gob fills missing fields with zero values, so a step usually only seeds the new state); `Load` walks the chain and refuses saves it has no path for, or that are newer than the build.

**The rival** (`internal/sim/rivals`, `World.Rival`, tuning in `rivals.toml`) is one faction per run with a leader, a personality (`expansionist / defensive / opportunist / chaotic`) and a starting trust in the player from the seed. It moves in on `arrive_day` on a corner away from you, earns off its corners, claims free ones by personality up to `max_corners`, pushes on the corners of yours it borders (`Corner.Borders`, `World.Contested`; odds from its muscle on the front line against `rivals.Sim.Guard`: an enforcer, you, a runner), undercuts you there (`Corner.Squeeze` cuts the corner's `Share`, plus a small street-price drag) and tips off the police while it holds a grudge. `SendEnforcers(corner, force)` is the player's answer, on the `events.Force` dial `warn / push / hit`: `rivals.Sim.Odds` is what the picker shows and what the dice use, heat scales with the corner, and every strike or push feeds `Rival.War`; past `crackdown_threshold` the police clear both sides' front line. A corner won by force is held with nobody on it, so post a runner before it drifts. `harness.Warlike` and `cmd/balance -policy war -force F -rival P` measure it; `rivals_test.go` in the harness pins the acceptance criteria (a passive player loses corners to an expansionist within 60 days, a hit war reaches the patrol line faster than aggressive selling, ownership / cash / muscle / squeeze invariants). The expansionist is the hard draw: it keeps pushing past its cap at half pace, so a player who never guards or fights loses ground for as long as they let it.

**Diplomacy is the table** (#32, `rivals.toml [diplomacy]` and `[deal.*]`, `game/diplomacy.go`, `sim/rivals/diplomacy.go`, `ui/diplomacy.go`): deals are state on the rival (`Rival.Trust` 0-100, `Rival.Deals`, `Rival.Betrayed`), offers are on the world (`World.Offers`), and everything is proposed, answered, kept and broken inside the rival's step. Three kinds ship: a **truce** (`Terms.Days`; no pushes, no undercutting, no tips, and it ends with `DealEnded` at the close of its last night), **tribute** (`Terms.PerDay`, dirty cash the rival step moves each night, `TributePaid`; it leaves every corner of yours alone until you stop paying) and a **split** (`Terms.Corners`, the ids on the player's side of the line: the rival neither claims nor pushes on them, `Post` refuses a free corner past the line, and `World.SplitLines` are the three lines the UI offers). A deal holds on ticks before `Until` (`Deal.Live`), `World.Deal(kind)` asks about the coming tick, and `World.AtPeace` is a truce or a tribute. The joint shipment (`DealShipment`) is listed and refused with `ErrNoRoutes` until #30 lands; `joint_trust` is in the table for it. Player actions queue intent: `Propose(kind, terms)` (one a day, checked for shape; `Withdraw`), `Accept(id)` (moves the offer to `World.Accepted` scratch, sealed the next morning on exactly the offered terms) and `Decline(id)`; `Abandon` records the corner in `World.Abandoned` scratch so the step can notice a split corner walked off. The rival's answer is `rivals.Sim.Chance`: the kind's `base`, the terms' `Favour` (-1 the hardest ask to 1 the easiest: a short truce, a fat tribute, a modest line; a split past `split_fair + split_trust x trust` or over a rival corner is refused outright) times `terms`, `accept_trust` at full trust, the personality's `deal_bias`, `accept_war` at a full war, and `fear_deal` from `reputation.toml [effects]`; zero for `distrust_days` after a betrayal (`Sim.Distrusted`) or on a night the enforcers go in. The dialog shows that number and the dice use it. The rival offers too (`offer`, one on the table at a time, `offer_days` to answer, `personality.offer_chance` per day its situation calls for one): an expansionist that cannot pay its muscle `low_cash_days` asks for a truce, an opportunist with `upper_hand` times the guard on the front line demands tribute at the middle cut, a defensive one asks for the long truce once the war is loud, a chaotic one with a front line asks for the short one. Every night a deal holds earns `trust_kept` (times `Scale(respect, respect_trust)`) and, for a truce or a split, `respect.deal_kept` in the reputation sim, which reads `w.Rival.Deals` after the rival step has ended what ran out; a strike costs `force.X.trust`. **Betrayal** is a push or a hit under any deal (every deal breaks), a missed tribute or a split corner abandoned: trust to `betrayal_floor`, `Rival.Betrayed` stamped, one `RivalTippedPolice` that night whatever else happens, `DealBroken{By: "you"}`; a chaotic rival breaks deals at `personality.betrayal` per deal-night (`DealBroken{By: "rival"}`, its trust untouched), the others never. The crackdown ignores deals. `betrayal_spread` is in the table for Phase 4. Events: `DealOffered`, `DealAccepted`, `DealRefused`, `DealBroken` have headlines; `DealEnded` and `TributePaid` are report-only. Schema 8 seeds trust on a pre-#32 save (`Rivals.MigrateDiplomacy`, after #30's 6 -> 7 city step). The rival lives in the home city, so the split lines, the street value a tribute is a cut of and the front line an opportunist weighs are all `w.Home()`'s. The rivals screen (8) is the panel: trust bar, the war, live deals with days left, offers with the cursor, `d` opens the two-page propose dialog (kind, then three terms with odds), `y` / `x` answer the selected offer; the dashboard's RIVALS panel carries trust and whatever holds or waits. `harness.Diplomat` and `diplomacy_test.go` pin the acceptance: a truce holds (no push, take, tip or undercut) and the rival is back the day after it lapses, the diplomat holds more ground than the passive player against an expansionist and runs cooler than a hit war, a defensive rival never breaks a deal over the horizon and a chaotic one does, offers lapse and seal as offered, a betrayal floors trust and nothing is accepted for `distrust_days`, the corner invariants hold through a split, and trust, deals and offers survive a save. The rival's offer roll is one more draw from the tick RNG on the days its situation calls for one, so pinned-seed tests that read a single day can shift when the rival's mood does (`TestHeldDemandIsServed` reads the run's peak).
**Upgrades are multipliers the sims read.** `internal/content/upgrades.toml` is the tree: `[[upgrade]]` nodes with a branch (`operations`, `security`, `legal`), a cost (dirty unless `clean = true`; the `retainer` is the clean-cash node, so it is only buyable once the fronts have washed something), `requires` and an `[upgrade.effects]` table of named multipliers and deltas; the file header fixes how each name combines across owned nodes (product, sum, lowest or highest wins) and decode refuses an unknown effect name or a prerequisite not defined earlier. `World.Upgrades` is the owned set; `World.BuyUpgrade(tree, id)` (`game/upgrades.go`) checks existence, ownership, prerequisites and the right cash pool, applies at once and is not per-day scratch (only `UpgradesToday`, which the market sim reports as `UpgradeBought`, is). `game.FoldEffects(w, tree)` folds the owned set into a plain `game.Effects`; the market and heat sims call it at the top of `Step` and multiply their own tuning by it (supplier price, buy pressure, fill; sale heat, decay, lie-low, patrol cap, response cooldown, sting and raid losses, evidence per bust, `evidence_arrest`), so no sim reads another. The one delta to player state, `carry_bonus`, lands on `Player.CarryLimit` at purchase. The Legal branch lives in the heat sim: the lawyer thins what a bust adds, the retainer lets a point of evidence go cold every `evidence_decay_days` without a new one (`Heat.EvidenceDay`; #27's rule still holds, a quiet-day sting adds nothing and does not reset the clock), and the fall guy takes the first indictment or arrest once (`World.FallGuyUsed`, `FallGuyBurned`). Tuning rules of thumb: heat multipliers cannot make an always-aggressive player last longer, because heat saturates and the DA's file then grows at the response cooldown, so the Security branch's survival lever is `cooldown_bonus`; make it strong enough to keep heat under the sting threshold and aggressive play becomes safe, which is worse. `TestSecurityBranchSoftensAggressive` and `TestUpgradedBeatsManaged` pin both ends.

**Snitching** (#13, `crew.toml [informant]`, `heat.toml informant_*`) is the crew sim and the heat sim talking through the world. A member under both the loyalty and the nerve line rolls daily to turn (`CrewMember.Informant`, the hidden flag; the roster never shows it, `Stats.Informants` counts them); the crew sim emits `CrewTurnedInformant`, which has no headline on purpose and which the heat sim consumes only to start its clock (`Heat.LeakDay`). From then on, every `informant_days`, the heat sim adds `informant_evidence` pages to `Heat.Evidence` and resets `Heat.EvidenceDay` whatever was sold and whatever the lawyer's `evidence_cut` says (a witness is not a bust), so an informant is the one exception to #27's rule and the reason the retainer's decay is worth having; it adds `informant_heat` that is deliberately left out of the `HeatChanged` reasons. The tells are therefore in the report: a "the DA's file on you grows" line under a heat delta with no sting or raid, and a delta the dial does not add up to. `Heat.Leaks` counts them, resets to zero once nobody on the payroll is talking, and at two the dashboard and crew screen hint "Somebody is talking." A raid while one is on the payroll takes the whole stash (`Enforcement.Stash`). The player's answers: `World.Investigate(cost)` queues a night's questions (`World.Investigation`, per-day scratch, paid up front from dirty then clean cash) that the crew sim resolves with `crew.Sim.InvestigateOdds` (base, plus the best enforcer's skill, plus `investigate_learn` per empty night in `Crew.Investigated`; the UI shows the same number), naming an informant into `Crew.Exposed` (the roster marks them SNITCH) or costing everyone `investigate_loyalty`; `World.PayOff(id, cost, loyalty)` buys loyalty at once, not silence; and `Fire`, which is the only thing that stops an informant, and which the crew do not hold against you when it was one (`CrewFired.Informant`). At the quit threshold a member walks as before unless the rival holds ground, in which case they defect (`CrewDefected`, `Rival.Leads`, `Stats.Defections`): the rival sim, next step, adds them to its muscle and walks onto the corner they ran if nobody stands there (`CornerTaken.Handed`), or pushes at the usual odds if somebody does; a corner in another city is no lead at all (the rival lives at home: the crew sim hands over none and the rival sim refuses one, `TestDefectionElsewhereHandsNoCorner`). `harness.Plant` puts an informant on the payroll from day 0, `harness.Vigilant` is the crewed player who investigates once the tell has shown twice and fires whoever is named, and `snitch_test.go` pins the acceptance: the always-quiet player with a plant is indicted within `harness.SnitchDays`, the vigilant one survives, a skill-90 enforcer names the informant within three nights on every seed and a skill-10 one takes materially longer, a defection is a rival corner gain the next day. An audit (#29) is the other way in: the laundering sim, stepping after heat, turns the least loyal accountant under the same loyalty line with no dice (`laundering.Sim.flip`, `TestAuditFlipsTheAccountant`), and because heat never sees that tick's event it stamps `LeakDay` every day nobody is talking, so the clock runs from the audit either way. None of the new world fields needed a schema bump: their zero values are the pre-#13 state.
**Lieutenants run a city for you** (#31, `crew.toml [lieutenant]`, `[lieutenant.personality.*]` and `[role.lieutenant]`; `sim/crew/lieutenant.go`; `ui/lieutenant.go`). A lieutenant is a crew member (`CrewMember.Personality`, fixed at generation from `violent / greedy / careful / steady` and hidden until `Observed`; `City`, `Assigned`) and everything they do is a policy over the actions the player has, run inside the crew step for each city that has one (`World.Assign(id, city)` / `Unassign`, one per city; `CrewState.Lieutenant(city)`): nothing new is simulated, only who decides. Candidates are lieutenants with `chance` only once the player holds corners in two cities (`crew.LieutenantsWanted`; the roll is only made then, so a one-city run draws the pool it always did), and an *assigned* lieutenant adds `[role.lieutenant].crew` slots to the roster (`crew.Sim.MaxCrew(w)`; `Hire` takes the cap from the caller), which is how a six-strong crew staffs a second city. Every night, after the roster has settled: the cut (`[role.lieutenant].cut` of their city's takings, `Stats.Cuts`) and a greedy one's `skim` on top, at any loyalty, come off dirty cash first (the skim is folded into the day's `CrewSkimmed`); under `flip` loyalty they turn informant with no dice (`LieutenantFlipped`, hidden like `CrewTurnedInformant`: the heat sim starts its clock on it and, while a lieutenant is talking, files `[lieutenant].evidence` pages a leak instead of `informant_evidence`); at `quit_threshold` one running a city **walks with it** (`crew.Sim.walk`: every corner held there bar the one you stand on goes to the rival if it holds ground in that city, else to the street, the stash there is emptied, `LieutenantWalked`, `Stats.Walked`); then delegation (`crew.Sim.delegate`, no dice): the crew come off a corner robbed twice since it was claimed (`Corner.Robbed`, counted by the territory sim and forgotten `drift_days` after the corner goes back to the street), idle runners go on the best corners there (a held one nobody works, else the biggest free one; `Post` refuses a split corner, so the next is tried, and a claim's `Since` is set to the tick so the territory sim reports it in the morning), idle enforcers guard the worked ones if the temper's `guard` says so, whatever is held with no runner is abandoned (never the player's own corner or one a live split covers), and every product in the stash gets a **standing order** at the temper's `dial` (`World.Delegated`, keyed like `Orders`, refreshed nightly and dropped on `Unassign`, `Fire` or a walk; `World.StandingOrder`). The market resolves a standing order only where the player placed no order of their own (`PlayerSold.Standing`), and every `PlayerSold` in a run city carries `Lieutenant` / `LieutenantName`, which the crew sim uses for the cut and the heat sim for the temper's `heat` multiplier (`heat.Sim.LieutenantHeat`, inside `SaleHeat` so the dial preview is honest). Lying low is everyone's day off. `LieutenantActed` is report-only bookkeeping for what they did and what it cost; the report names the temper once they have run a city for `reveal_days` (`Observed`). The zero values are the pre-#31 state, so no schema bump. Acceptance in `harness/lieutenant_test.go`: the delegated player never places an order at home once a lieutenant has it and home sells on standing orders (unassigned nightly, it sells nothing); on one seed and policy a violent lieutenant's city is hotter at day 60 than a careful one's, a greedy one keeps less of the same takings as a steady one and a careful one takes less; a lieutenant at loyalty 0 walks the next night with every corner unheld and the stash gone; the player's order for a product wins the day; a flip is dice-free and files thicker pages; lieutenants only come looking with two cities held; assignment, temper and standing orders survive a save and the run replays; and `delegated` at `steady` is within 20% of `distributor` at the horizon (`harness.Delegate` puts one on the payroll for a test). Balance: the lieutenant adds corners, not a heat budget or the rival's forbearance, so the tier-4 row stays pending (see `moneyCurve`); a violent one in a delegated run can raid the operation into an arrest, which is the temper working as designed under a policy too blunt to fire them.

**All tuning is data.** `internal/content/*.toml` is embedded and decoded into `content.Config`; sims take their config struct at construction (`sim.Default`). Balance changes should be TOML edits, verified with `cmd/balance` and the harness tests in `internal/harness/balance_test.go`, and `crew_test.go`, which pin the difficulty curve (always-aggressive gets indicted fast, always-quiet survives and earns less, managed beats quiet, crewed beats managed) and the crew invariants (loyalty monotone in pay, no skim above the threshold). `TestMoneyCurve` pins the economy's scale (issue #24): one row per progression tier giving the band the best policy's median net worth must land in at that tier's checkpoint (`harness.TierDays`); a phase that ships a tier's multiplier adds that tier's row (tier 1 `managed`, tier 2 `crewed`; tier 3 `laundered` and tier 4 `delegated` are in the table but `pending`, measured and logged rather than enforced: `laundered` sits near $1.1M at day 120 against a $5M-$20M band and `delegated` near $1.9M at day 200 against $50M-$200M, $2.7M with a steady lieutenant, $2.6M for `distributor`. #31 added the volume #52 asked for, a lieutenant's people working every free home corner, and it moved the number by tens of percent, not tens of times: the rival takes four to ten of home's ten corners in most seeds (these policies never fight or deal), heat caps what a city moves under the sting line whatever the corner count, and the ceiling of both cities fully worked with no rival and no heat is about $20M by day 200 at today's prices and demand, so those rows wait on a price or demand multiplier, not on staffing). `TestIdleMarketStaysNearEquilibrium` allows 25% because supply shocks (a slump cuts demand, not price) hold an idle market's mean about a fifth over base in every city. `laundering_test.go` pins the wash invariants (pools never negative, a day's wash never over capacity, frozen fronts wash nothing, greedy washes more and is audited more than careful, an audit is evidence only when greedy, laundered beats crewed). Day counts in the harness (`harness.Horizon`, `TierDays`, `-days`) are where the tooling *looks*, never a run length: the game has no day cap, a run ends only through an ending, and the player sets the pace. Do not add mechanics that end a run merely for playing on (#27 removed the one that did). `territory_test.go` pins the corner invariants: served demand is exactly the worked corners' share, losing every runner loses every corner within `drift_days`, and no corner means nothing sells. Products above the starting three are gated by `unlock_cash` in `market.toml`: the market sim lists a product the first day after peak cash reaches it. Sale heat is per unit moved (`sale_heat` per `street_units` heat-weighted units), so heat scales with volume, not with how many products exist.

**Dilemma cards** (#15, `internal/content/dilemmas.toml`, `game/dilemmas.go`, `sim/news/dilemmas.go`, `ui/card.go`) interrupt the day with a choice. The news sim, last in the order, deals at most one a day from the day's RNG: none for `min_gap` days after the last, then a chance rising each day to certainty at `max_gap` (one roll a day whatever happens, so the stream is fixed for the seed), then a weighted pick over the eligible cards with ones already drawn thinned by `1/(1+drawn)` and `once` cards retired. `[card.trigger]` fields (`content.CardTrigger`) must all hold, and the ones that name somebody fill the slots (`news.Slots`: the least loyal member under `loyalty_below`, the most loyal over `loyalty_above` or of `role`, the biggest worked corner for `corners`, the pair for `contested`, the first front) deterministically, no dice; `news.Eligible` is that check and `TestTriggersHold` tables it. The card is rendered when drawn (`game.Card`, text, choices and effects included) into `World.Dilemmas.Pending`, so a save on a card restores it without the content and `World.Choose(i)` resolves it: effects apply at once through `applyEffect`, the one function that knows every key in `game.EffectKeys` (a key it does not know is an error; `news.New` refuses a deck with one, so a typo fails at start-up), the outcome goes in the journal with source `dilemma`, and `Dilemmas.Answered` (per-day scratch) carries the optional follow-up headline for the news sim to print the next morning. Cash keys clamp at zero, heat/loyalty/war at 0..100; `*_amount` keys are multiples of the card's `Amount` (`amount_share` of dirty cash, at least `amount`, rounded to two figures) so a card can name a sum and then take it; `fear`, `respect`, `notoriety` move `Player.Reputation` at once, clamped to 0..100, and the reputation sim applies its sum cap that evening as it does to every source. The UI shows the card in `modeCard` before the report (`showCard`): `1-3`/`enter` decide, the outcome shows, a second `enter` opens the report, and `enter` never ends the day; `continueRun` reopens a pending card. The deck's convention is that the last choice is what doing nothing gets, and that is `harness.Decline`; `harness.Run`/`RunFrom` play with the deck boxed (the invariants they pin belong to the other sims), `RunWith(..., Chooser)` deals it and answers before the policy acts. `harness/dilemmas_test.go` pins determinism (same seed, same choices, same cards on the same days), a save on a card replaying identically, and every card in the deck being dealt and rendering without a hole; `news/dilemmas_test.go` pins the deck's shape, the pacing and the unknown-key refusal. The zero value of `DilemmaState` is the pre-#15 state, so no schema bump.

**Cash formatting** in the UI: `cash()` (`internal/ui/format.go`) compacts totals (`$45K`, `$1.2M`, `$3.4B`) for the title bar, dashboard, report and run summary; `money()` keeps exact figures for itemised amounts (fees, wages, a purchase); `price()` is per-unit (cents under $1,000).

**UI** (`internal/ui`) is one Bubble Tea `Model` with a `mode` state machine (start menu, play, dilemma card, buy/sell dialog, ship dialog, fund dialog, report, help, confirm-new, confirm-fire, confirm-end, confirm-upgrade, confirm-travel, post picker, strike picker, front picker, propose dialog, game over) and a `screen` tab (dashboard, market, journal, crew, map, upgrades, ledger, rivals). `Model.city` is the city the market and map screens are turned to (`shown()`); it follows the player when they travel, `[`/`]` cycle it on any screen and left/right cycle it on the market (`cycleCity`), the map's cursor is an index into the shown city's corners, and `actionCity()` is what `s`, `t` and `x` act on: the shown city on the market and map, where the player is everywhere else. Key handling is split: `handleKey` dispatches by mode, `keyDialog` owns the buy/sell flow (product -> quantity -> dial; a buy is where you are, `w` at the quantity switches to wholesale lots where the city sells them and the offer is open), `keyShip` owns the ship flow (`ship.go`: product -> route -> quantity -> dial, the dialog collapsing each step to a line once it is chosen so it fits 80x24), `keyPlay` owns the main screen; `t` opens the ship dialog and `g` asks before travelling (`modeConfirmTravel`) anywhere, `h`/`f` hire and fire only on the crew screen (`f` on the ledger funds a city), and `t` there gives the selected lieutenant a city through a picker (`lieutenant.go`, `modeAssign`; the last row takes it away), `c`/`e`/`a`/`w` post a runner / post an enforcer / abandon / send the enforcers only on the map screen (`map.go`, `rivals.go`; the pickers are `modePost` and `modeStrike`; posting yourself on the other city's map explains that you have to go there), `u` buys the selected node only on the upgrades screen (`upgrades.go`; three columns walked as one list, `modeConfirmUpgrade` asks first), `b` on the ledger buys a front through a picker (`ledger.go`, `modeFront`) and buys from the supplier everywhere else, `d` on the rivals screen opens the propose dialog (`diplomacy.go`, `modePropose`: kind, then terms, `esc` goes back a page) and cycles the launder dial everywhere else, `y` / `x` on the rivals screen answer the selected offer (`x` cancels an order elsewhere), `p` cycles the pay dial anywhere (`l` stays lie-low, `w` is the map's war key). The map shows the routes out of the shown city and what is on the road under the grid; the market shows the other city's price and where else you hold the product; the dashboard is the city you are in, with a line for what is stashed elsewhere and on the road, and the heat panel names the other city's heat; the report has a SHIPMENTS section. Rival corners are purple on the map; the dashboard's RIVALS panel shows the leader, corner count, personality (once observed) and the war meter. Up/down move the cursor on every screen and left/right move within it, never between tabs (`tab` / `shift+tab` and the digits do that): the map is walked as a grid (`mapMove`, the cursor stays an index into the shown city's `Corners` so the pickers are unaffected), the upgrades tree crosses its columns at the same row (`upgradeMove`), the market turns to the other city, dialogs move the dial, and the other screens ignore them. `n` ends the day at once; `enter` on the play screen opens a confirmation (`modeConfirmEnd`) and only a second `enter` or `y` ends it, except on the upgrades screen where `enter` is the buy key and asks before buying. Inside dialogs, the card and the report `enter` confirms and closes and must never advance the day (`TestEnterDoesNotEndDay`, `TestCardBeforeReport`). UI test seeds are wall-clock and cards come from day 5 on, so tests that play past day 4 end days with the `endDay` helper, which answers a card if one shows. Layout must fit 80x24 and 120x40 (`TestRendersAtCommonSizes`; its `assertFits` also fails on a modal wider than the terminal, which wraps its border), and the ticker must never exceed terminal width. The title bar drops to short tab names and then digits as width runs out; long lines on a screen should be `truncate`d, not left to wrap (the report and the help truncate their lines to the modal). Colours live in `internal/ui/theme`, one accent per sim.
